> （`apkanalyzer` 复核调试包与发布包均不含它）。`ACCESS_NETWORK_STATE` 仍会出现在合并后的清单里，

## 0. 先说三个必须由你拍板的前提（否则方案会走偏）

### 0.1 发音方案是一次方向调整，与上一轮交付相反

上一轮的需求是「**移除对系统 TTS 作为主要发音方案的依赖**，实现真正区分的美式/英式」；本轮需求是
「**删除美式/英式选项**，改用系统 TTS」。两者直接冲突，我按**本轮需求执行**，但把代价写在明面上：

| 维度 | 上一轮（真实录音 + 双口音） | 本轮（系统 TTS，单一口音） |
| --- | --- | --- |
| 音质 | 真人录音，自然 | 取决于设备引擎，机械感强 |
| 覆盖 | **受录音库限制**：实测美式 11/14、英式仅 1/14 | **任意单词都能读**，覆盖率问题消失 |
| 离线 | 首次需联网下载，之后离线 | 取决于引擎；多数引擎离线可用，**但语音包可能需要用户先下载** |
| 权限 | 需要 `INTERNET` + `ACCESS_NETWORK_STATE` | **可以删除这两个权限**，隐私声明「不申请 INTERNET」重新成立 |
| 代码量 | 约 913 行主代码 + 387 行测试 | 删除上述代码，新增约 350～450 行 TTS 封装 |
| 口音 | 美/英各自独立文件 | 只有一条音轨，**无法提供英式**（本轮需求即如此） |

**需要你确认**：如果「英式发音」是产品卖点或宣传点，本轮改动等于放弃它。若只是希望「读得出、读得准、
不折腾用户」，本方案完全成立，而且顺带修掉了上一轮最大的遗留问题（英式覆盖率 1/14）。

### 0.2 平台范围：当前只有一个 Android 原生应用

需求 1.7 提到「桌面端、移动端和不同浏览器」。**当前仓库是 Android 原生应用，不存在 Web / 桌面目标**，
因此该条无法在本代码库内「保证兼容」。可选路径：

* **A（推荐，可立即执行）**：本轮只做 Android，把 TTS 抽成平台无关的 `SpeechService` 接口
  （见 §5），未来接 Web（`window.speechSynthesis`）或桌面（Windows SAPI / macOS `say`）时只增实现类。
* **B**：本轮同时立 Web 端。这是**新产品面**，需要独立技术栈、独立打包与独立测试体系，
  不是当前 Compose 代码可以顺带完成的 —— 需要单独立项与排期。

### 0.3 「按指标验证效果」与当前「无任何统计 SDK」的冲突

需求 5.7 要求用次日留存、学习完成率等指标验证。当前应用**刻意不接入任何账号、广告或统计 SDK，
数据只在本机**（这是既有承诺，也写在应用内隐私说明里）。三种做法，我建议第 1 种：

1. **本地度量（推荐）**：关键指标在设备上计算并在「设置 → 学习数据诊断」中展示；
   用户主动导出备份时才带出。零隐私成本，可立即落地。
2. **匿名聚合上报**：需要新增远端、隐私政策、合规评估，与现有承诺冲突。
3. **线下可用性测试**：邀请 5～8 位用户完成任务并记录，用于「进度可理解性」这类主观指标。

## 1. 当前问题分析

### 1.1 发音：三处具体缺陷 + 一次方向调整

| # | 问题 | 证据 |
| --- | --- | --- |
| P1 | 口音选项是**决策负担**且英式几乎无内容 | 上一轮实测：英式录音仅 1/14；两个胶囊按钮占用卡片空间，但一半情况下点了也还是合成音 |
| P2 | TTS 曾被降级为「兜底」，其工程缺陷因此长期存在 | 旧 `PronunciationPlayer` 在引擎未就绪时**直接 return**，首次点击无反应 —— 该缺陷已在上一轮修复，但 TTS 整体仍不是一等公民 |
| P3 | 例句**无法朗读** | 当前只能读单词；`WordCard` 的播放按钮只接收单词文本 |
| P4 | 系统默认语速/音调**未被尊重** | 现有实现自行 `setLanguage`，从不读取系统 TTS 偏好；用户改了系统设置，应用里没有变化 |
| P5 | 失败路径提示粗糙 | 只有一句「无法播放」；没有设置入口、没有重试建议 |

### 1.2 学习进度：数据齐全，但「呈现层级」和「下一步」缺失

这是本方案最重要的发现：**统计数据层已经基本完备**，缺的是产品化表达。

已经存在（可直接复用，无需新建表）：

* `TodayPlan`（`domain/study/StudyModels.kt`）：`dueCount`、`remainingNew`、`plannedCards`、
  `doneCards`、`progressFraction`、`accuracyTodayPercent`、`isFinished`、`hasNothingToDo`
* `StatsSnapshot`（`domain/stats/StatsModels.kt`）：`statusCounts: Map<MasteryStatus, Int>`（**已掌握/学习中/待复习
  的词典可直接得出**）、`streakDays`、`longestStreakDays`、`todayMinutes`、`totalMinutes`、
  `accuracyPercent`、`reviewCompletionPercent`、`activeMistakeCount`、`highMistakeCount`、
  `LevelProgress`（已学/已掌握比例）、`StageGoal(label, current, target)`、
  `weekly` / `monthly` / `calendar`（逐日 studiedWords / correct / fuzzy / wrong / duration）
* `hasAnyData`：**已经为「数据不足」状态预留了开关**

真正缺失的是：

| # | 问题 | 说明 |
| --- | --- | --- |
| Q1 | 首页**只有今日计划环**，看不到「已掌握 / 学习中 / 待复习」的分布 | 这些数字埋在统计页底部 |
| Q2 | 首页**不显示今日学习时长** | `todayMinutes` 只在统计页 |
| Q3 | 首页**没有「下一步该做什么」的具体一句** | 有「开始背单词」按钮，但没有「还需复习 12 个词」这类量化指引 |
| Q4 | 阶段目标只在统计页，且**没有说清口径** | 用户不知道 `StageGoal` 的分子分母怎么来的 |
| Q5 | 首次使用/回归用户的引导**不成体系** | 有空状态文案，但没有「先做什么」的三步引导 |
| Q6 | 首页信息密度已经偏高（问候+环形+4 指标+周趋势+最近记录+恢复卡片） | 继续加内容会过载，必须先做**减法与重排**（见 §3） |

### 1.3 学习分析：完全没有「主动分析」这一层

现状：统计页呈现**事实**（正确率、趋势、日历），但不做**判断**，也不给**建议**。

* 没有任何代码根据数据得出「你最近只学新词、没复习」这类结论；
* 错题只按「错误次数/时间/分类」列表展示，没有把错误**归因**（题型、词性、时间间隔）；
* 考试已按题型统计正确率（成绩页有「各题型正确率」），但**没有把「四选一题型正确率显著偏低」变成建议**；
* `SessionSummary.encouragement`（`StudyModels.kt`）只有按正确率分档的 5 条固定文案，
  与「连续天数、是否回归、是否破纪录」等状态无关。

### 1.4 用户激励：位置单一、状态无关

* 激励只在**会话结束页**出现，且只按正确率分档；
* 首页、连续学习区、进度面板**没有任何激励内容**；
* 没有「破纪录」「回归」「目标达成」这些高价值时刻的识别；
* 没有频次控制概念 —— 一旦在多处加入激励，很容易变成打扰。

### 1.5 整体体验

* 首页已接近信息过载，需要「一层结论 + 一层细节」的分层；
* 提示语气不统一（有的页面是数字直陈，有的是鼓励句）；
* 异常反馈不统一：TTS 失败、导入失败、数据不足三种情况的表达方式各不相同。

## 2. 产品改进方案

### 2.1 总原则

1. **复用已有数据层**，不新增统计表（本方案只新增 1 个本地偏好键与 1 个纯函数层）。
2. **把「判断」和「表达」分离**：`domain/insight/` 只产出结构化结论（纯 Kotlin，可单测），
   文案模板集中在 UI 层，便于改文案不改逻辑。
3. **首页只回答四个问题**（需求 5.2）：我现在到哪了 / 最近表现如何 / 下一步做什么 / 给我的建议是什么。
4. **不制造焦虑**：所有百分比为空时不显示 0%，所有建议最多 2 条，语气统一为「客观描述 + 一个动作」。

### 2.2 发音（对应需求一）

* 删除美式/英式选项与相关界面；删除网络音频模块（`data/pronunciation/` 全部、
  `ui/speech/PronunciationController.kt`、`AudioFormatTest` / `PronunciationRepositoryTest` /
  `PronunciationSourceTest` / `AccentSelectionTest`）。
* **顺带删除** `INTERNET`、`ACCESS_NETWORK_STATE` 权限与隐私说明里的联网段落 —— 隐私承诺回到
  「除系统 TTS 外不联网」。
* 新建 `data/speech/`：`SpeechService` 接口 + `SystemTtsSpeechService` 实现 + 系统默认值读取 +
  可用性判定；`ui/speech/SpeechController.kt` 提供 UI 状态机；`ui/components/SpeakButton.kt` 统一按钮。
* 朗读范围扩大到：**单词、例句（英/中可分别控制）、单词详情页整块文本**。
* 语速/音调：优先读取系统 TTS 偏好；读不到时**不覆盖**引擎默认值（见 §5.4）。

### 2.3 学习进度（对应需求二）

* **首页改为一屏四段式**（详见 §3.1）：今日进度 → 词汇状态分布 → 下一步 → 一条建议（+ 一条激励）。
* 首页新增：
  * 「下一步」行动卡：一句量化指引 + 一个主按钮（如「还需复习 12 个词 → 开始复习」）；
  * 词汇状态三色条（已掌握 / 学习中 / 待复习，直接来自 `statusCounts`）；
  * 今日学习时长（`todayMinutes`，与统计页同一口径）；
  * 阶段目标进度条（复用 `StageGoal.percent/remaining`）。
* **阶段目标需要一个真实的发现与修正**：现有 `StatsCalculator.stageGoal()` 的
  `target` 是**整个词库**（CET-4 = 3,849 词），因此一个刚入门的用户会看到
  「完成 CET-4 词库 · 320 / 3849 · 还差 3,529 词」—— 这不是激励，而是压力；而且需求 4.2 的
  「完成阶段目标时激励」在这种设计下**几乎永远不会触发**。
  改为**里程碑制**：`[50, 200, 500, 1000, 2000, 全部]`，展示「下一个里程碑：500 词，还差 180」，
  并在跨过每个里程碑时触发一次激励（与 §6 的「达成阶段目标」场景对接）。
  这是纯领域层改动（`StageGoal` 增加 `milestones` 或新增 `MilestoneProgress`），有单测保护，风险低。
* **减法**：把「最近学习记录」从首页移到统计页（它属于"回看"而不是"决策"）；
  周趋势压缩为 7 根细柱（保留，因为它是"最近表现"的唯一图形证据）。
* 每个数字都可点开查看**统计口径**（一行说明 + 「如何计算」展开），口径定义见 §4.1。
* 首次使用/无数据：显示三步引导卡（选级别 → 设每日目标 → 开始第一组），而不是空环。

### 2.4 学习分析（对应需求三）

* 新增纯函数层 `domain/insight/`：输入 `LearningSignals`（从 `StatsSnapshot` + `TodayPlan` +
  会话/考试数据派生），输出 `List<Insight>`。
* 首批实现 **8 条规则**（可单测，阈值集中常量）：
  1. 只学新词、复习不足；2. 正确率下降；3. 错题集中在某题型；4. 遗忘回潮（early-lapse）；
  5. 学习频率下降；6. 单次时长过长且正确率下滑；7. 某批薄弱词建议优先复习；8. 数据不足（明确说明）。
* 每条 `Insight` 必须带：**结论 + 依据数字 + 一个可执行动作 + 原因**；最多展示 2 条，
  其余折叠为「查看更多」。
* 「数据不足」由样本量阈值控制（如作答 < 20 次或活跃天数 < 3 天 → 不出判断，
  只显示「目前数据有限，再学 X 次就能给你更准确的建议」）。

### 2.5 用户激励（对应需求四）

* 新增 `domain/motivation/MotivationEngine`：输入 `MotivationContext`（场景 + 数字），
  输出一条 `MotivationMessage(text, tone, source?)`。
* 6 个场景（需求 4.2）：完成学习 / 破连续纪录 / 中断后回归 / 正确率提升 / 达成阶段目标 / 遇到困难。
* **文案全部原创**（见 §6.4 的版权策略），不引入外部名言，避免版权与「空洞鸡汤」两个问题。
* 频次控制：同一场景每天最多 1 次；首页激励位每天最多 1 条；用户可一键「今天不再显示」。

## 3. 页面和交互设计建议

### 3.1 首页信息层级（重排后的目标形态）

```
┌──────────────────────────────────────────────┐
│ 早上好，今天也要加油            连续 6 天 🔥 │  ← 问候 + 连续天数（已有）
├──────────────────────────────────────────────┤
│ ① 今日进度（第一眼）                          │
│   ◯ 环形：12 / 20 已完成                     │
│   已学 12 · 正确率 75% · 时长 18 分钟        │
├──────────────────────────────────────────────┤
│ ② 下一步（最重要的一句话）                    │
│   还需复习 12 个词，约 6 分钟                 │
│   [ 开始复习 ]        [ 继续背新词 ]          │
├──────────────────────────────────────────────┤
│ ③ 词汇状态分布（一眼看清结构）                │
│   ██████░░░░ 已掌握 320 · 学习中 180 · 待复习 12│
├──────────────────────────────────────────────┤
│ ④ 阶段目标（里程碑制，见 §2.3）              │
│   CET-4 进度 8% · 下一个里程碑：500 词       │
│   还差 180 词 · ▓▓▓▓░░░░░░                   │
├──────────────────────────────────────────────┤
│ ⑤ 给你的建议（最多 2 条，可展开）             │
│   · 你连续 3 天只学新词，建议今天安排 10 分钟复习│
│     [ 去看看这些词 ]                          │
│   · 目前数据有限，再学 8 次就能给出更准确建议  │
├──────────────────────────────────────────────┤
│ ⑥ 今日一句（激励，每天最多 1 条）             │
│   「今天的坚持，正在变成未来的自信。」        │
├──────────────────────────────────────────────┤
│ ⑦ 未完成会话恢复卡（仅在有时显示）            │
└──────────────────────────────────────────────┘
        （「最近学习记录」移到统计页）
```

设计要点：

* 顺序即优先级：**一眼是进度、二眼是行动**。用户不需要滚动就知道下一步做什么。
* ①③④ 全部使用**同一种进度组件**（环形 + 横条 + 三色条），视觉语言统一。
* ⑤ 建议卡与 ⑥ 激励卡**外观区分**：建议用中性信息色 + 图标 + 动作按钮；激励用暖色细边框、无按钮，
  避免用户误以为激励也是待办事项。
* 每张卡都支持「空状态」：无数据时显示引导文案，不留白。

### 3.2 学习完成页（会话总结）

现有内容：正确/模糊/不认识计数、正确率、用时、错词、再练错词。
新增：**一条与本次会话状态匹配的激励**（例：本次是回归后的第一组 → 「重新开始本身，就是一种进步。」）
+ 一条下一步建议（错词 ≥ 5 → 「这 5 个词已进错题本，明天优先复习效果最好」）。

### 3.3 连续学习区

连续天数旁增加「最长纪录 N 天」与破纪录时的即时反馈（一次性轻提示，不弹窗抢占）。

### 3.4 统计页

* 保留现有全部内容（趋势、日历、题型正确率）；
* 新增「学习分析」分区：把 §2.4 的 8 条规则中未在首页展示的结论列出（最多 3 条）；
* 新增「统计口径」折叠说明（§4.1 的文案）；
* 新增「发音服务状态」（§5.6）。

### 3.5 交互与无障碍统一规则

| 场景 | 规则 |
| --- | --- |
| 主按钮 | 每屏只有一个主按钮；首页主按钮随「下一步」变化 |
| 空状态 | 必须包含：一句解释 + 一个动作按钮（不允许只有插画或空白） |
| 加载 | ≤ 300 ms 不显示 loading（避免闪烁）；> 300 ms 显示骨架/进度 |
| 失败 | 一句人话原因 + 一个恢复动作（重试/设置/稍后） |
| 数字 | 一律整数百分比；分母为 0 时不显示百分比而显示「暂无数据」 |
| 无障碍 | 所有可点区域 ≥ 48dp；进度条与环形提供 `contentDescription`（如「今日进度 60%，12/20」）；支持 200% 字体缩放不截断 |
| 动画 | 复用现有 `AppTheme.motion` 开关；新增动画不得绕过该开关 |

## 4. 数据指标和分析逻辑

### 4.1 统计口径（必须对用户可见，直接决定数据可信度）

| 指标 | 定义（与现有实现一致） | 边界说明 |
| --- | --- | --- |
| 学习日 | **04:00 为分界**（`StudyDay`），凌晨学习算前一天 | 已在代码中实现并有测试 |
| 今日已学 | 当天**首次作答**的不同单词数（不是作答次数） | 同一词多次作答只计 1 |
| 今日正确率 | 正确作答数 / 当日作答总数；分母 0 → 显示「暂无」 | 不显示 0% |
| 已掌握 | `user_word_progress.status == MASTERED`（连续多次正确、间隔 ≥ 7 天） | 见 `SpacedRepetition` |
| 学习中 | `status == LEARNING` | 与「待复习」互斥 |
| 待复习 | `dueAt <= now` 且状态非「已掌握」 | 首页与错题本同一口径 |
| 连续学习天数 | 相邻学习日均有作答的最长连续段；昨天有学习则今天仍延续 | 支持「昨天仍算连续」 |
| 今日学习时长 | 会话内答题间隔累计（单次间隔上限封顶，防止挂机） | **必须写明封顶规则** |
| 复习完成率 | 当日已复习词数 / 当日到期词数 | 到期为 0 → 「暂无」 |
| 阶段目标 | 现有实现（`StatsCalculator.stageGoal`）是**单一目标**：`label = "完成 CET-4 词库"`，`current = 已学词数`，`target = 词库总词数` | **本方案建议改为里程碑制**，理由见 §2.3 |

> 口径文案放到 `docs/` 与应用内「统计口径」面板，二者由**同一份常量/文案源**生成，避免文档与界面不一致。

### 4.2 分析逻辑（8 条规则的可计算定义）

记：`A` = 近 7 天作答数，`acc7` = 近 7 天正确率，`accPrev7` = 前 7 天正确率，
`newRatio` = 近 7 天新词作答 / 总作答，`activeDays7`、`minPerDay7`（中位数）、
`examTypeAcc`（各题型正确率）、`lapseRate`（已掌握词在 14 天内回落到模糊/不认识的比例）。

| 规则 | 触发条件（阈值集中为常量，可调） | 输出建议（示例） |
| --- | --- | --- |
| R1 只学新词、复习不足 | `newRatio ≥ 0.8` 且 `dueCount ≥ 10` | 「你连续 3 天只学新词，建议今天先花 10 分钟复习 12 个到期词。」 |
| R2 正确率下降 | `A ≥ 20` 且 `acc7 ≤ accPrev7 - 8`（百分点） | 「本周正确率比上周低 9%，建议放慢新词速度，先把错题过一遍。」 |
| R3 题型薄弱 | 某题型 `n ≥ 10` 且 `examTypeAcc ≤ 60%`，且低于其他题型均值 ≥ 15 点 | 「四选一题型正确率 52%，明显低于其他题型（78%），建议做 1 组四选一专练。」 |
| R4 遗忘回潮 | `lapseRate ≥ 0.25` | 「有 25% 的已掌握词又变模糊，建议把复习间隔调回更短的一组。」 |
| R5 学习频率下降 | `activeDays7 ≤ 3` 且此前 14 天活跃 ≥ 8 天 | 「最近 7 天只学了 3 天，建议先恢复每天 10 分钟的小目标。」 |
| R6 时长过长且效率下降 | `minPerDay7 ≥ 45` 且 `acc7 < accPrev7` | 「你最近单次学习超过 45 分钟但正确率在降，试试拆成两次 20 分钟。」 |
| R7 薄弱词集中 | 某批错词 ≥ 8 个且共现同一词性或同一后缀（如过去式） | 「你最近对过去式相关词汇错误率较高，建议今天优先复习这 15 个词。」 |
| R8 数据不足 | `A < 20` 或活跃天数 < 3 | 「目前数据有限，再学 8 次左右就能给你更准确的建议。」（**不给其他判断**） |

**实现要点**：全部为纯函数，输入一个 `LearningSignals` 数据类，输出 `List<Insight>`；
`Insight` 携带 `ruleId`、`severity`、`evidence: Map<String, Number>`，便于单测断言
「同一份输入必然得到同一条建议」。规则之间做**优先级排序 + 去重**，最多输出 2 条给首页。

### 4.3 产品指标（本地度量，需求 5.7）

| 指标 | 本地定义 | 观测方式 |
| --- | --- | --- |
| 学习完成率 | 当日 `doneCards ≥ plannedCards` 的天数 / 有打开记录的天数 | 设置 → 学习数据诊断 |
| 复习完成率 | 复用 `reviewCompletionPercent`，看 7 日均值 | 同上 |
| 连续学习天数 | `streakDays` 分布（当前/最长） | 同上 |
| TTS 成功率 | 成功播放次数 / 播放尝试次数（分「引擎不可用」「语言缺失」「无异常」三类计数） | 同上（这是 §5 的核心验收指标） |
| 进度可理解性 | 5～8 人任务测试：能否在 10 秒内说出「我下一步要做什么」 | 线下测试记录（文档化） |
| 次日留存 | 次日有任意作答的天数比例 | 本地计数器（不联网） |

> 所有计数只存本机、只用于本机展示与用户主动导出；在「隐私说明」中写明用途（需求 3.8 的最小化原则）。

## 5. TTS 功能实现建议

### 5.1 分层（关键：让「平台」可替换）

```
domain/speech/SpeechRequest.kt      纯数据：text, localeTag, rate?, pitch?, queueMode
domain/speech/SpeechStatus.kt       sealed：Ready / Initialising / LanguageMissing /
                                    EngineUnavailable / VoiceDataMissing / Failed(code)
data/speech/SpeechService.kt        接口：status: StateFlow, speak(), stop(), release(), openSystemTtsSettings()
data/speech/SystemTtsSpeechService.kt   Android 实现（TextToSpeech）
data/speech/SystemSpeechDefaults.kt  读取系统 TTS 偏好（null 安全）
ui/speech/SpeechController.kt         UI 状态机：Idle / Loading / Playing / Stopped / Failed
ui/components/SpeakButton.kt          统一播放按钮（四态 + 无障碍）
```

这样做的意义：需求 1.7 的多端诉求，未来只需新增 `WebSpeechService` / `DesktopSpeechService` 实现，
UI 与状态机不动。**本轮只实现 Android 实现**（见 §0.2）。

### 5.2 引擎选择与语言

* 使用 `TextToSpeech(context, listener)` 的**默认引擎**（即用户在系统设置里选定的引擎），
  不硬编码引擎包名 —— 这正是需求 1.2/1.3 的落地方式。
* 语言选择顺序：① 用户为「朗读语言」显式选择的语音（应用内可选，默认「跟随系统」）；
  ② 系统默认 TTS 语言（见 §5.4）；③ 当前词库语言（英语 `en`）。
* 逐词朗读时用 `setLanguage(Locale.ENGLISH)`；若返回 `LANG_MISSING_DATA` / `LANG_NOT_SUPPORTED`
  → 进入 §5.5 的错误分支，**不静默失败**。
* 例句中文翻译朗读同理（`Locale.CHINESE` 或跟随系统），并提供开关（默认关闭，避免打断英语语感）。

### 5.3 播放按钮的四态（需求 1.6）

| 状态 | 视觉 | 行为 |
| --- | --- | --- |
| Idle | 喇叭图标 | 点击开始朗读 |
| Loading | 图标内小进度圈 + 禁用 | 初始化引擎 / 等待 `onInit` |
| Playing | 高亮图标（可换成停止/暂停） | 再次点击 = 停止（见下） |
| Failed | 图标变错误色 + 一行说明 + 「去设置」 | 提供恢复路径 |

**可实现性提醒（重要）**：Android `TextToSpeech` **没有原生的暂停/继续**（只有 `stop()`）。
因此：

* **v1 方案**：按钮语义为「播放 / 停止」，文案一致，避免出现假暂停；
* **若确需暂停/继续**：必须走 `synthesizeToFile()` 合成到应用缓存，再用 `MediaPlayer` 播放
  （可暂停、可拖动），代价是首帧延迟与一次磁盘写入。建议做成 v2 可选项，
  接口上预留 `SpeechRequest.pauseSupported`。

### 5.4 「使用系统设置中的默认语言、声音、语速、音调」（需求 1.4）

这一条需要**精确实现**，因为 Android 不会自动把系统偏好交给应用：

* 应用可读 `Settings.Secure` 中的 TTS 相关键（`TTS_DEFAULT_SYNTH`、`TTS_DEFAULT_RATE`、
  `TTS_DEFAULT_PITCH`、`TTS_DEFAULT_LOCALE`）——**需在设备上验证可读性**：部分厂商 ROM 或权限策略
  下可能返回 `null` 或抛异常。
* 实现策略（`SystemSpeechDefaults`）：
  1. 读取上述键，**任何一项读不到就不设置该项**（不要用应用自己的默认值覆盖引擎默认值）；
  2. `rate` / `pitch` 仅在成功读到且落在合理区间（如 `0.5f..2.0f`）时才调用 `setSpeechRate` / `setPitch`；
  3. 全部包在 `runCatching` 内，失败不影响播放。
* 「声音」：优先 `tts.defaultVoice`（引擎给的默认声音）；用户在应用内选择过则用其选择。
* 结果：**用户改系统设置 → 应用下次朗读即生效**；应用不成为"第二套设置"。

### 5.5 异常与降级（需求 1.5：提示 + 入口 + 不崩溃 + 备用方案）

| 情况 | 判定 | 用户可见反馈 | 恢复动作 |
| --- | --- | --- | --- |
| 引擎初始化失败 | `onInit(ERROR)` / 超时 3 s | 「系统语音服务未就绪，可能是引擎未安装或被禁用。」 | 按钮：**打开系统 TTS 设置**（`ACTION_ACCESSIBILITY_SETTINGS`，TTS 输出设置位于其中） |
| 缺少语音数据 | `LANG_MISSING_DATA` | 「缺少英语语音包，安装后即可朗读。」 | 按钮：**安装语音数据**（`TextToSpeech.Engine.ACTION_INSTALL_TTS_DATA`）；失败则退化为打开系统设置 |
| 语言不支持 | `LANG_NOT_SUPPORTED` | 「当前语音引擎不支持英语。」 | 建议切换引擎（打开系统设置） |
| 播放中异常 | `onError(utteranceId)` | 「朗读失败，请重试。」 | 按钮：重试；连续 2 次失败 → 提示去设置 |
| 完全无 TTS | 无可用引擎 | 「本机没有可用的语音服务。」 | **备用方案**：显示音标 + 「跟随系统」不可用时提供「查看音标/真人发音不可用」的说明，并把按钮切换为「查看音标」模式（不假装能播放） |

设计原则：**任何失败都必须有一个可点的下一步**，且绝不能崩溃（所有 TTS 调用 `runCatching` 包裹，
回调只更新状态流）。

### 5.6 发音服务状态（可诊断性）

设置页新增「发音」分区：

* 当前引擎名（`tts.defaultEngine`）、默认语言/声音、生效的语速与音调（并标注「来自系统设置」或
  「引擎默认」）；
* 试听一句（「The quick brown fox…」英文 + 一句中文），用于用户自检；
* 本机 TTS 成功率与失败分类计数（§4.3），一键清零；
* 「打开系统 TTS 设置」入口。

### 5.7 朗读范围与调用点

| 位置 | 朗读内容 | 备注 |
| --- | --- | --- |
| 学习卡 | 单词（主按钮）+ 例句（次级小按钮） | 例句按钮仅在例句非空时显示（当前内置词库例句为空，需优雅隐藏） |
| 单词详情 | 单词 + 例句 + 释义（中文） | 三个独立按钮 |
| 错题本行 | 单词 | 长按朗读可选 |
| 考试页 | **默认不朗读**（闭卷不得提示答案） | 硬约束，需写在代码注释与测试里 |

### 5.8 兼容性矩阵（需求 1.7 的 Android 侧兑现）

| 维度 | 处理 |
| --- | --- |
| API 26–36 | 只用 API 26 起可用的 `TextToSpeech` API；语音列表 `voices`（API 21+）可用 |
| 无 Google 服务的设备 | 不假设 Google TTS 存在；使用默认引擎并处理「无引擎」分支 |
| 厂商 ROM 差异 | 系统设置键读取全部 null 安全；不因读不到而失败 |
| 屏幕尺寸/字体 | 按钮 ≥ 48dp；说明文案可换行；200% 字体不截断 |
| 静音/勿扰/音频焦点 | 朗读前请求音频焦点可选项；静音模式下给出轻提示（避免用户以为坏了） |

## 6. 激励内容展示策略

### 6.1 展示位置与频次

| 位置 | 内容 | 频次上限 |
| --- | --- | --- |
| 首页激励位 | 1 条与当前状态匹配的语句 | 每天 1 条，可「今天不再显示」 |
| 会话完成页 | 1 条与本次表现/场景匹配的语句 | 每次会话 1 条 |
| 连续学习区（破纪录时） | 一次性轻提示「连续 7 天，新纪录」 | 每个纪录值 1 次 |
| 阶段目标达成 | 达成瞬间的卡片变化 + 1 条语句 | 每个目标 1 次 |
| 困难时 | 1 条降低压力的语句（不显示正确率红字） | 每天 1 条 |

**打扰控制**：任一时刻最多 1 条激励；不做弹窗、不做震动；不在答题过程中插入；不阻断任何操作。

### 6.2 状态 → 内容映射（`MotivationEngine`）

| 场景（输入条件） | 语句示例（原创） |
| --- | --- |
| 完成今日计划 | 「完成今天的学习，你已经比昨天更接近目标。」 |
| 破连续纪录 | 「连续 6 天，这是你自己的新纪录。」 |
| 中断 ≥ 3 天后回归 | 「重新开始本身，就是一种进步。」 |
| 正确率环比 +5 点以上 | 「这周的正确率比上周高，方法是对的。」 |
| 达成阶段目标 | 「已掌握 500 词 —— 这个数字是你一次次答对攒出来的。」 |
| 遇到困难（正确率 < 40% 或错词多） | 「错误不是退步，而是告诉你下一步该练习什么。」 |
| 默认/兜底 | 「你不需要一次学会所有内容，只需要比昨天多掌握一点。」 |

实现：`MotivationContext(moment, streakDays, isNewStreakRecord, daysSinceLastStudy, accuracyDelta, goalJustReached)` →
`MotivationMessage(text, tone, source = ORIGINAL)`；选择逻辑纯函数，**同一上下文输出稳定**（可单测）。

### 6.3 文案质量约束（避免空洞）

* 每条语句必须**具体**（含数字或明确动作）或**真诚地承认努力**，禁止「加油！你是最棒的！」这类空话；
* 不使用比较级羞辱（「别人已经…」）、不使用倒计时施压（「再不学就来不及了」）；
* 长度 ≤ 30 字，避免在首页占三行。

### 6.4 版权策略（需求 4.4）

* **v1 全部使用原创语句**（本方案提供的示例均为原创），因此无版权风险，也不需要署名；
* 若未来确实要引入名言：只使用**明确公共领域**的作者与作品（如 1930 年以前出版、作者逝世逾 70 年），
  逐条在数据文件中记录 `author` / `work` / `year` / `source`，并在界面署名；
* **禁止**抓取来源不明的「励志语录」站点；无法确认权利的一律不用；
* 数据文件中为每条外部引用保留 `license` 字段，缺失时构建期校验失败（可加单测守住）。

- [ ] 单词、例句、详情页文本均可朗读；考试页**不可**朗读（有测试守护）。
- [ ] 播放按钮具备 Idle / Loading / Playing / Failed 四态，且 **Loading 在 300 ms 内完成时不闪烁**

- [ ] 引擎不可用 / 缺少语音包 / 语言不支持 三种情况均：显示可读提示 + 提供入口 + **不崩溃**

## 9. 可能的风险、边界情况和解决方案

| # | 风险 / 边界 | 影响 | 解决方案 |
| --- | --- | --- | --- |
| 1 | 删除真人录音后音质下降，用户感知为"退步" | 体验 | 在「发音」设置里如实说明"使用系统语音服务"；提供试听让用户先确认；若后续要恢复高质量，保留 `SpeechService` 接口以便并行接入 |
| 2 | 设备无 TTS 或未下载语音包（尤其国行 ROM） | 功能不可用 | §5.5 的分支 + 安装入口 + 「查看音标」备用路径；应用不崩溃 |
| 3 | 系统 TTS 键读取被厂商限制 | 语速不生效 | 读不到就不设置（不覆盖引擎默认）；在「发音」里显示"来自引擎默认"，避免误导 |
| 4 | `TextToSpeech` 无原生暂停 | 交互承诺落空 | v1 用「播放/停止」语义；v2 用 `synthesizeToFile` + `MediaPlayer` 实现真暂停 |
| 5 | 中文引擎读英文单词口音奇怪 | 学习误导 | 单词强制 `Locale.ENGLISH`；若引擎不支持英语 → 明确提示"当前引擎不支持英语"，建议切换引擎（不静默用中文读） |
| 6 | 首页继续加内容 → 信息过载 | 违反需求 5.5 | 已做减法（最近记录移出首页）；建议最多 2 条；激励每天 1 条；新增区块必须挤掉旧区块或折叠 |
| 7 | 统计口径被误解（如"今日已学"是不同词数） | 信任 | 数字可点开口径说明；文档与界面同源；边界一律显示「暂无」 |
| 8 | 建议过多或不准 → 用户反感 | 激励反效果 | 最多 2 条 + 严重度排序 + 数据不足不出判断 + 每条建议可关闭（记本地偏好） |
| 9 | 时长统计被挂机污染 | 数据不准 | 沿用单次间隔封顶；在口径说明中写明封顶规则 |
| 10 | 语速过快导致听不清 | 学习无效 | 应用内提供「朗读速度：跟随系统 / 慢速 / 常速」三档（慢速时 `setSpeechRate(0.8f)`），默认跟随系统 |
| 11 | 隐私担忧（新增诊断指标） | 合规 | 全部本地计算、不联网；隐私说明写明用途；诊断数据仅随用户主动导出 |
| 12 | 删除发音模块导致既有测试失效 | 回归 | 明确删除 3 个测试类（`AudioFormatTest` 4 + `PronunciationRepositoryTest` 12 + `PronunciationSourceTest` 8 = **24 个用例**），把 `AccentSelectionTest`（2 个用例）改写为「朗读语言跟随系统 TTS」；迁移清单见 §10 |
| 13 | 例句为空导致朗读按钮落空 | 空状态 | 例句按钮仅在内容非空时渲染；内置 ECDICT 词库无例句，因此首版该按钮多数情况会隐藏（如实说明） |
| 14 | 破纪录/目标达成的"一次性提示"重复触发 | 打扰 | 用 DataStore 记录"已庆祝"的纪录值与目标值，仅在值变化时触发（单测覆盖） |
